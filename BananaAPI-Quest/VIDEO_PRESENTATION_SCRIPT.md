**What to show on screen:**
1. Open `frontend/js/game.js` in VS Code.
2. Scroll to `startTimer()`, `stopTimer()`, `updateTimerDisplay()`, and `handleTimeout()`.
3. Highlight DOM event listeners: `submitButton.addEventListener("click", ...)`, `restartGameBtn.addEventListener("click", ...)`, and keyboard events `event.key === "Enter"`.

**What to say:**
> *"Next is **Theme 2: Event-Driven Programming**.*
>
> *In event-driven software, execution flow is determined by events such as user actions, timer ticks, or messages from other programs. Our application utilizes event-driven mechanics across three distinct dimensions:*
>
> *First, **Timer-Driven Interval Events**. In `game.js`, the `startTimer()` function establishes a recurring interval using `setInterval()`, firing a tick event every 1,000 milliseconds. With every tick, the timer updates the DOM and dispatches visual state changes: when time drops below 10 seconds, it triggers an amber warning animation; below 5 seconds, it adds a pulsating danger class. When the clock hits zero, a `handleTimeout()` event is generated, clearing the interval, deducting a life, and transitioning the game state.*
>
> *Second, **User Interface and DOM Events**. We register non-blocking event listeners on buttons (`click`) and input fields (`keydown` for Enter key detection). These handlers decouple user actions from business logic, ensuring the browser remains responsive.*
>
> *Third, **Asynchronous I/O and Promise Events**. Communicating with the backend is entirely non-blocking. Using `fetch()` with `async`/`await`, HTTP request and response cycles are handled through the JavaScript Event Loop microtask queue. When calling the external API on the server, we also leverage an `AbortController` timeout event to abort hanging requests after 10 seconds.*
>
> *Justifying our approach: an event-driven architecture is essential in modern web systems because a single-threaded runtime like JavaScript would freeze completely under synchronous polling or blocking sleeps. Event listeners and asynchronous event loops guarantee a smooth, 60fps user experience."*

### 🟣 Part 5: Theme 4 - Virtual Identity (`7:30 - 9:15`)
**What to show on screen:**
1. Open `backend/controllers/authController.js` (highlight `bcrypt.hash(password, 12)` and `jwt.sign`).
2. Open `backend/middleware/authMiddleware.js` (highlight Bearer token extraction and `jwt.verify`).
3. Open `backend/models/User.js` (show `password: { select: false }`).

**What to say:**
> *"Our fourth theme is **Virtual Identity**.*
>
> *A virtual identity is a digital representation of a user that enables persistent authentication, access control, and personalized state tracking. In BananaAPI-Quest, we implement a robust security pipeline:*
>
> *First, **Credential Protection**. In `authController.js`, passwords are never stored in plaintext. We utilize `bcryptjs` with **12 salt rounds**. This produces an irreversible cryptographic hash with an embedded unique salt, rendering precomputed rainbow table attacks and dictionary attacks mathematically unfeasible. Furthermore, in our Mongoose `User` schema, the password field is configured with `select: false` so that accidental database queries never leak hashed credentials.*
>
> *Second, **Stateless Token-Based Authentication (JWT)**. Upon successful login, the server issues a JSON Web Token signed with a cryptographically secure `JWT_SECRET` and an expiration window of 2 hours. The token payload encodes the user's virtual identity—their unique `ObjectId` and email.*
>
> *Third, **Route Authorization Middleware**. In `authMiddleware.js`, every protected route checks the `Authorization: Bearer` header. The middleware verifies token cryptographic integrity, validates expiry, and binds `req.user` to the request context. If the token is forged or expired, access is immediately rejected with an HTTP 401 Unauthorized status.*
>
> *Critically comparing alternative approaches: we evaluated traditional **Stateful Session Cookies**. While cookies with `HttpOnly` flags offer strong protection against XSS, they require server-side session memory or Redis databases to store session state, creating bottlenecks when horizontally scaling across multiple servers. Additionally, cookies are inherently vulnerable to Cross-Site Request Forgery (CSRF). Stateless JWTs, by contrast, are self-contained, horizontally scalable across server clusters, and platform-agnostic, making them the industry standard for modern distributed architectures."*
